# Data Model: Todo Web Application Backend API

## Entity Definitions

### User Entity
**Description:** Represents a system user with unique identifier

**Fields:**
- **id** (Integer, Primary Key, Auto-increment)
  - Unique identifier for the user
  - Automatically generated by the database
- **created_at** (DateTime, Default: current timestamp)
  - Timestamp when the user record was created
- **updated_at** (DateTime, Default: current timestamp, Updated: on change)
  - Timestamp when the user record was last updated

### Task Entity
**Description:** Represents a todo item with properties like title, description, status, and associated user identifier

**Fields:**
- **id** (Integer, Primary Key, Auto-increment)
  - Unique identifier for the task
  - Automatically generated by the database
- **title** (String, Max length: 100, Required)
  - Title of the task (1-100 characters)
- **description** (String, Max length: 1000, Optional)
  - Detailed description of the task (0-1000 characters)
- **status** (String, Values: "pending", "completed", Default: "pending")
  - Current status of the task
- **user_id** (Integer, Foreign Key to User.id, Required)
  - Reference to the user who owns this task
- **created_at** (DateTime, Default: current timestamp)
  - Timestamp when the task was created
- **updated_at** (DateTime, Default: current timestamp, Updated: on change)
  - Timestamp when the task was last updated

**Relationships:**
- **Task belongs to User** (many-to-one relationship)
  - Each task is associated with exactly one user
  - Multiple tasks can belong to the same user
- **User has many Tasks** (one-to-many relationship)
  - Each user can have zero or many tasks
  - Tasks are isolated by user_id to ensure privacy

## Validation Rules

### Task Title Validation
- **Min Length:** 1 character
- **Max Length:** 100 characters
- **Required:** Yes
- **Constraint:** Cannot be empty or null

### Task Description Validation
- **Max Length:** 1000 characters
- **Required:** No (optional field)
- **Constraint:** Can be empty or null

### Task Status Validation
- **Allowed Values:** "pending", "completed"
- **Default Value:** "pending"
- **Required:** Yes
- **Constraint:** Must be one of the allowed values

## State Transitions

### Task Status Transition
- **Current State:** "pending"
- **Possible Transition:** "completed"
- **Action:** User marks task as completed

- **Current State:** "completed"
- **Possible Transition:** "pending"
- **Action:** User marks task as pending again

## Database Constraints

### Primary Keys
- Both User.id and Task.id are primary keys with auto-increment
- Ensure uniqueness of entity identifiers

### Foreign Key Constraint
- Task.user_id references User.id
- Maintains referential integrity
- Prevents orphaned tasks without valid users

### Not Null Constraints
- Task.title cannot be null
- Task.status cannot be null
- Task.user_id cannot be null

### Check Constraints
- Task.status must be in ('pending', 'completed')
- Task.title length must be between 1 and 100
- Task.description length must be between 0 and 1000

## Indexes

### User Entity
- Primary key index on id (automatically created)

### Task Entity
- Primary key index on id (automatically created)
- Foreign key index on user_id (for efficient user-based queries)
- Index on (user_id, status) for efficient filtering of user tasks by status

## Data Integrity Measures

### Transaction Support
- All operations wrapped in database transactions
- Ensures ACID properties (Atomicity, Consistency, Isolation, Durability)
- Maintains data consistency even in case of errors

### Concurrency Handling
- Database-level locking mechanisms prevent race conditions
- Ensures data integrity when multiple requests access the same data
